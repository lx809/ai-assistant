## 1. 项目背景

### 1.1 业务背景

个人用户的知识与信息散落在笔记、文档、网页和对话中，缺少一个能统一沉淀、随时检索并结合个人背景回答的助手。同时，模型 API 与工具生态日趋成熟，个人开发者可以在本地搭建一套"私有知识 + 对话 + 工具调用"的助手系统，兼顾隐私、可控与可扩展性。

本项目面向单一个人用户，在本地 Windows 环境运行。对话模型使用云端 DeepSeek API，个人知识索引与数据全部保存在本机。

### 1.2 问题陈述

当前个人资料无法被统一检索和问答，普通聊天助手没有长期记忆，也无法替用户执行"记笔记、保存网页"等动作。现成的助手产品无法满足"数据留在本机、过程可观察、能力可编程扩展（MCP）"的需求。

### 1.3 项目目标

- 提供一个浏览器可访问的本地 Web 聊天助手，支持流式对话；
- 让助手能检索用户私有知识库并展示引用来源；
- 让助手具备跨对话的长期记忆，且记忆对用户透明、可删改；
- 通过 MCP 标准接入"记笔记、网页抓取入库"等工具，并预留扩展能力；
- 建立可测试、可调试的工程基础，便于后续增加日历/提醒等工具。

## 2. 用户分析

### 2.1 目标用户

| 用户角色 | 描述 | 核心需求 |
|----------|------|----------|
| 使用者（本人） | 在 Windows 本地使用助手的个人用户，无既有数据，主要诉求是沉淀知识、检索问答、获得带长期记忆的对话体验 | 多轮流式对话；文档上传后可问答；让它记笔记、存网页；记住我的偏好并跨对话生效 |
| 调试者/维护者（本人兼任） | 关注系统行为、模型决策与工具调用质量 | 在界面上看到工具调用过程与检索来源；健康检查；本地日志 |

### 2.2 用户画像

用户为个人开发者/技术型用户，熟悉 Python 与 PyCharm 开发环境，使用 Windows 系统。机器仅有 4GB 显存的 NVIDIA 显卡，因此大型模型本地推理不现实，对话采用 DeepSeek 云端 API，嵌入等轻量计算在本地完成（GPU 不足时退回 CPU）。用户当前没有现成知识库，需要助手能主动帮助沉淀内容。

### 3.2 详细功能描述

#### 3.2.1 流式对话与过程展示

**功能描述**：

用户在浏览器发起对话，后端通过 SSE 事件流返回：会话建立、记忆注入摘要、工具调用开始/结束、RAG 命中来源、回答增量与最终完成状态。单 Agent 由 LangChain 编排，对话模型使用 DeepSeek。

**用户故事**：
- 作为使用者，我希望回答能逐字流式显示，以便尽快看到结果；
- 作为调试者，我希望看到每次工具调用与检索来源，以便理解回答依据并排查问题。

**验收标准**：
- [ ] 打开网页可进行多轮流式对话，回答逐字出现；
- [ ] 工具调用前后界面出现 `tool_start`/`tool_end` 记录与结果摘要；
- [ ] 回答引用知识库时展示来源卡片，可查看命中片段；
- [ ] 客户端断开后停止生成，已产生的消息仍保存。

**输入**：用户消息文本。
**输出**：SSE 事件流（`session_start`、`memory_loaded`、`tool_start`、`tool_end`、`sources`、`token`、`done`、`error`）。
**业务规则**：
- 单 Agent、工具调用型，最多限制调用轮数避免死循环；
- 模型回答需基于检索结果，不编造来源；
- 工具失败不中断回答，Agent 如实说明或换方式完成。

#### 3.2.2 长期记忆

**功能描述**：

系统在 SQLite 中保存结构化记忆条目（类型、内容、来源会话、时间）。对话开始前注入记忆摘要；对话结束后调用一次独立的 DeepSeek 请求，克制地提炼高置信度长期事实并去重写入。用户在网页可查看、编辑、删除记忆条目。

**用户故事**：
- 作为使用者，我希望告诉助手"记住我叫 XX / 我喜欢简洁回答"后，重启服务仍生效；
- 作为使用者，我希望随时查看和删除助手记住的内容，以保证隐私可控。

**验收标准**：
- [ ] 对话中产生的新记忆在后续新会话中被注入；
- [ ] 自动提炼不重复已有内容，明显随口的闲聊不会被保存；
- [ ] 网页可查看、编辑、删除记忆，删除后不再注入；
- [ ] 手动编辑的条目不被自动提炼覆盖。

**输入**：对话消息、用户对记忆的显式操作。
**输出**：`memory_entries` 记录；对话开始时的记忆摘要。
**业务规则**：
- 记忆类型：`identity` / `preference` / `ongoing` / `decision` / `general`；
- 自动提炼为异步任务，不阻塞回答；
- 提炼使用独立系统提示词，要求克制并做语义去重。

#### 3.2.3 知识库检索问答（RAG）

**功能描述**：

本地解析文档（Markdown/TXT/PDF/Word），切块后用本地中文嵌入模型（`BAAI/bge-small-zh-v1.5`）向量化，存入 Chroma。回答时默认检索 top-5 相关块，随 `sources` 事件展示来源。

**用户故事**：
- 作为使用者，我希望上传文档后能直接提问文档内容；
- 作为使用者，我希望每个回答能看到引用来源，必要时打开原文核对。

**验收标准**：
- [ ] 上传四种支持格式的文档后可检索问答；
- [ ] 重新导入同一文档不产生重复向量；
- [ ] 检索结果带来源路径、摘要与相似度，界面可展开；
- [ ] 无 GPU 时嵌入模型自动使用 CPU 并正常工作。

**输入**：入库文档、用户问题。
**输出**：命中切片（来源、摘要、分数）与基于切片的回答。
**业务规则**：
- 单块约 500 字，相邻块重叠约 10%，优先按 Markdown 标题切分；
- 以内容哈希判断文档变更，同文档先删旧向量再入库；
- 解析失败的文档记录状态，不阻塞其他任务。

#### 3.2.4 文档导入与索引

**功能描述**：

提供网页上传与文件夹扫描两条入库路径，解析、切块、嵌入与写入在后台执行，完成后更新文档状态。

**用户故事**：
- 作为使用者，我希望拖拽/选择文件即可入库并看到状态；
- 作为使用者，我希望把文件放进指定文件夹后扫描一次即可入库。

**验收标准**：
- [ ] 上传接口限制文件类型与大小，非法文件返回明确错误；
- [ ] 文档状态包含待处理/索引中/已完成/失败；
- [ ] MCP 工具写入的文件也能被同一索引入口处理。

**输入**：multipart 文件或扫描指令。
**输出**：文档记录、索引状态、向量写入结果。
**业务规则**：路径经知识根目录校验，防止路径穿越；索引任务不阻塞对话接口。

#### 3.2.5 MCP 工具（记笔记与网页抓取）

**功能描述**：

首批两个能力实现为本地 MCP Server（stdio），Agent 通过 MCP 客户端调用：`notes.create` 把用户口述内容写成 Markdown 笔记；`web.save` 抓取链接正文清洗后保存。保存路径若在知识根目录内，自动触发后台索引。

**用户故事**：
- 作为使用者，我希望对它说"记一下 XXX"，笔记出现在知识文件夹并能被后续检索；
- 作为使用者，我希望丢一个链接说"保存这篇文章"，正文入库后可问答。

**验收标准**：
- [ ] `notes.create` 生成带标题与时间戳的 Markdown 文件并可被检索；
- [ ] `web.save` 对可达网页抓取正文、清洗为 Markdown 并入库；
- [ ] 抓取失败返回明确原因；
- [ ] 新增第三方 MCP Server 仅需修改配置文件即可注册。

**输入**：笔记标题/内容/标签；网页 URL。
**输出**：写入成功的文件路径；触发索引。
**业务规则**：抓取仅限用户显式给出的 URL，限制响应大小与超时。

## 4. 非功能需求

### 4.1 性能需求

| 指标 | 要求 |
|------|------|
| 响应时间 | 网络正常时首字返回 < 3 秒；单次检索 < 1 秒 |
| 并发用户数 | 1 个本地用户（单会话为主） |
| 数据量 | 第一版支持数十万级切片的向量库规模即可，个人文档数千份以内 |

### 4.2 安全需求

- [ ] 数据加密（第一版数据仅存本机，不启用盘级加密；如后续部署他处需补充）
- [x] 权限控制：服务仅绑定 127.0.0.1，不做外部暴露
- [x] 审计日志：记录关键工具调用与错误到本地日志
- [x] 密钥保护：DeepSeek API Key 仅存 `.env` 且不入库
- [x] 路径校验：上传/写入路径限制在知识根目录内

### 4.3 可用性需求

- 一条命令启动后端，前端开发服务支持热更新；
- 提供 `/api/health` 检查 DeepSeek 配置、MCP Server 与嵌入模型可用性；
- DeepSeek 调用失败自动重试一次，仍失败给出清晰错误提示且不崩溃；
- 首次运行嵌入模型需联网下载，提供就绪状态与预下载方式。

### 4.4 兼容性需求

- 运行环境：Windows 10/11；
- 浏览器：Chrome / Edge 最新版本；
- 后端 Python 3.11+，前端 Node 20+；
- 无 NVIDIA GPU 时可运行（嵌入自动回退 CPU）。

### 4.5 可维护性需求

- 后端按 `api / agent / rag / memory / mcp_client` 模块划分，职责单一、接口清晰；
- MCP Server 列表、模型名、目录等均可配置化；
- 自动化测试覆盖解析、切块、向量库、记忆、API 与 SSE 链路；
- 本地日志便于定位模型决策与工具调用问题。

## 5. 数据需求

### 5.1 数据实体

| 实体 | 描述 | 关键属性 |
|------|------|----------|
| Conversation（会话） | 一次用户与助手的对话 | id、created_at、updated_at、title、summary |
| Message（消息） | 会话中的消息 | id、conversation_id、role、content、created_at |
| Document（文档） | 入库的原始文档 | id、filename、path、file_type、status、content_hash、error |
| DocumentChunk（切片） | 文档切块与向量 | id、document_id、text、embedding、metadata |
| MemoryEntry（记忆条目） | 长期记忆 | id、type、content、source_conversation_id、manual、created_at、updated_at |

### 5.2 数据流

1. 对话开始时：加载会话历史 + 注入长期记忆摘要 → 送模型；
2. 对话过程中：Agent 按需调用 RAG 检索（问题 → 向量化 → Chroma top-5）或 MCP 工具（写入 `knowledge/`）；
3. 工具写入文档后：触发后台索引（解析 → 切块 → 嵌入 → 写入 Chroma）；
4. 对话结束后：消息入库；异步提炼长期记忆并去重写入；
5. 网页端可查询会话、文档与记忆数据。

### 5.3 数据存储

| 数据类型 | 存储方式 | 保留策略 |
|----------|----------|----------|
| 会话与消息 | SQLite（`data/assistant.db`） | 本地持久化，用户删除前保留 |
| 长期记忆 | SQLite `memory_entries` 表 | 本地持久化，用户在界面可删除 |
| 原始文档 | 文件系统 `knowledge/` | 用户自行管理；删除文档时同步清理对应切片 |
| 向量切片 | Chroma（`data/vectorstore`） | 随文档删除/重新导入更新 |
| 运行日志 | 本地文件 `data/logs/` | 滚动保留 |

## 6. 接口需求

### 6.1 外部接口

| 接口名称 | 类型 | 提供方 | 用途 |
|----------|------|--------|------|
| DeepSeek Chat Completions | REST（OpenAI 兼容） | DeepSeek 云端 API | 对话生成与记忆提炼 |
| MCP 工具（notes.create、web.save） | MCP（stdio） | 本地 MCP Server | 写笔记、抓取网页入库 |
| 本地知识嵌入模型 | Python API | sentence-transformers | 文档/问题向量化 |

### 6.2 内部接口

| 模块 | 接口/职责 | 消费者 |
|------|-----------|--------|
| API 层 | `POST /api/chat`（SSE）、`/api/documents/*`、`/api/memory/*`、`/api/conversations/*`、`GET /api/health` | 前端页面 |
| Agent 核心 | 构建单 Agent、`astream_events` 事件流、工具注册 | API 层 |
| RAG | `index(doc)`、`search(query, top_k)`、状态查询 | Agent、API 层 |
| 记忆 | `list/create/update/delete`、`summarize()`、`extract(conversation)` | API 层、后台任务 |
| MCP Client | 按 `mcp_config.json` 启动并桥接 MCP 工具 | Agent 核心 |
| MCP Server | 暴露 `notes.create`、`web.save` 并写入 `knowledge/` | MCP Client |

## 7. 约束条件

### 7.1 技术约束

- 后端使用 FastAPI + LangChain，前端使用 Vue 3 + Vite；
- 对话模型固定走 DeepSeek OpenAI 兼容接口；DeepSeek 无官方嵌入 API，故嵌入本地完成；
- 向量库采用 Chroma，关系数据采用 SQLite；
- MCP 工具按标准 MCP 协议实现，不做私有工具协议；
- 本地 GPU 显存 4GB，模型选择须轻量且支持 CPU 回退。

### 7.2 业务约束

- 第一版仅单用户本地使用，不做账号、鉴权与多租户；
- 第一版不接日历/提醒/待办等第三方系统；
- 数据（文档、记忆、会话）默认只存本机，云端仅发送对话内容给 DeepSeek。

### 7.3 资源约束

- 运行依赖：Python 3.11+、Node 20+、Windows 系统；
- 网络依赖：首次需联网下载嵌入模型与前端依赖；运行时需访问 DeepSeek API 与用户指定的网页；
- 存储：预留知识文档、向量库与日志的本地磁盘空间。

## 8. 风险分析

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| Agent 工具调用陷入循环或偏离任务 | 高 | 中 | 限制最大调用轮数；工具结果过长时截断；过程面板暴露每轮决策便于观察 |
| DeepSeek API 不可用/限流/密钥错误 | 高 | 中 | 自动重试一次；清晰错误提示；健康检查 |
| 自动记忆提炼产生噪音或重复 | 中 | 中 | 克制型提炼提示词 + 语义去重 + 网页可删改 |
| 文档解析质量参差（PDF/Word） | 中 | 中 | 解析失败单文档标记失败，不阻塞；保留升级解析器空间 |
| 首次嵌入模型下载慢或失败 | 低 | 中 | 启动自检提示状态；提供预下载方式 |
| 4GB 显存不足导致本地嵌入性能差 | 低 | 低 | 自动回退 CPU；选用轻量中文小模型 |
| 网页抓取内容质量差或失败 | 低 | 中 | 抓取前校验；失败返回明确原因 |
